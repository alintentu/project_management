# Project Flow Insights README

This module introduces a domain-focused analytics layer that turns the existing task data into a project flow dashboard. `WorkflowStatus` defines the canonical progression of work (`backlog → in_progress → in_review → done`), validates every transition that reaches the insights layer, and protects the domain code from changes in the persistence enum. `InsightTask` captures the immutable facts about each task—identity, timestamps, assignees, tags, review notes—and provides just enough behaviour (`assign`, `tag`, `moveTo`, `estimateTrend`) to keep derived metrics accurate while remaining persistence-neutral.

`ProjectBoard` operates as the aggregate that stores InsightTask instances, replays their transitions, and derives the core metrics needed for delivery conversations. It counts how often work enters each column, computes a rolling weekly velocity, measures the proportion of tasks blocked in review, and flags emerging WIP-limit breaches so teams can react before delivery stalls. `ProjectDashboard` subscribes to the board’s status-change events, logging the live movement and exposing two high-level outputs: a quantitative `summary()` (status buckets, throughput, transition counters) and a qualitative `focusSuggestion()` that recommends the next action (clear review, reduce WIP, or replenish backlog).

On the application side, `ProjectFlowDashboardService` materialises the board from Eloquent models. It loads the project with its tasks and assignees, instantiates InsightTask objects, replays their workflow history to register transitions, and returns a ready-to-use dashboard object. `ProjectFlowDashboardController` binds that service to the `GET /projects/{project}/insights/flow` route, delivering a JSON payload that mirrors the dashboard summary and focus hint. Any authenticated consumer—Inertia pages, mobile client, or BI integration—can hit this endpoint to obtain a real-time pulse of project flow health without re-implementing analytics elsewhere.
